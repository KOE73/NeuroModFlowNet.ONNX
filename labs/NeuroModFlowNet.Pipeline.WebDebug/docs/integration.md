# Подключение

## Обязательные правила нового проекта

До реализации прочитать [docs/ui-principles.md](ui-principles.md) и [REQUIREMENTS.md](../REQUIREMENTS.md). При создании проекта:

1. Скопировать полный [docs/ui-principles.md](ui-principles.md) в документацию целевого проекта, например `docs/ui-principles.md`. При копировании внести в раздел «Общие стили и использование шаблона» фактическое расположение документов целевого проекта; ссылка на исходный шаблон не заменяет локальные правила.
2. В `AGENTS.md` проекта добавить обязательное указание: «Перед созданием или изменением UI прочитать и применять docs/ui-principles.md; это обязательные требования владельца». Путь сделать относительным и соответствующим реальному файлу; сохранить существующие инструкции.
3. В требованиях к UI проекта сослаться на этот локальный файл и добавить конкретные требования к реализации. Подробный стандарт хранить в одном месте; его размещение прямо в `AGENTS.md` допустимо для небольшого проекта.
4. Проверить существование всех указанных файлов и отсутствие противоречий между ними. В производных шаблонах сохранить тот же порядок переноса правил.

Не ограничиваться ссылкой на локальную папку исходного шаблона: полный стандарт должен оставаться доступным в самом проекте. Это относится к Blazor, другому web-стеку и native/MAUI/desktop.

Стандарт требует целостного рабочего обзора с совместно видимыми связанными данными и без лишнего дублирования, постоянных колонок для вертикального сравнения, выравнивания чисел/времени/X × Y, минимальной высоты однострочных записей, цвета существующего названия вместо лишних бейджей и подсказок для вторичных сведений. Проверять эти требования визуально при изменениях UI.

## Подключение Blazor (.NET 10)

Добавить ProjectReference на `src/TechnicalShell/TechnicalShell.csproj` либо перенести его в новое решение. В Program.cs зарегистрировать:

```csharp
builder.Services.AddScoped<TechnicalShell.UiText>();
builder.Services.AddSingleton(new TechnicalShell.ShellOptions
{
    AppName = "Application", Version = "v1", Environment = "development",
    StoragePrefix = "application.ui",
    Navigation = [
        new("Обзор", "", "chart-bar", Exact: true),
        new("Подключения", "connections", "plug"),
        new("Настройки", "settings", "settings", Exact: true, Settings: true)
    ]
});
builder.Services.AddRazorComponents().AddInteractiveServerComponents();
```

В App.razor подключить ресурсы в таком порядке:

```html
<link rel="stylesheet" href="_content/TechnicalShell/icons/tabler-icons.css" />
<link rel="stylesheet" href="_content/TechnicalShell/themes.css" />
<link rel="stylesheet" href="_content/TechnicalShell/shell.css" />
```

В Router использовать `DefaultLayout="typeof(TechnicalShell.Components.AppShell)"`. Router должен работать в интерактивном режиме. Страница добавляет свои данные в верхнюю строку:

```razor
<SectionContent SectionName="TopBarStats">
    <span>12 объектов</span><span>Обновлено 12:34:56</span>
</SectionContent>
```

Тексты оболочки — RU/EN ресурсы. Тексты нового приложения остаются его ресурсами. Пример дополняет перевод оболочки через UiText.AddTranslations; не копировать предметные строки в общий набор.

`NavItem.Children` задаёт дерево любой глубины. Приложение формирует его из своего списка подключений и ответов API, обновляет `ShellOptions.Navigation`, затем вызывает `ShellOptions.NotifyChanged()`. Смена данных меню не требует перезапуска. Имена demo в примере — вымышленные, не образец жёстко заданных имён реальных сервисов.

`Settings: true` отделяет пункт чертой и располагает его после рабочих пунктов. Родитель ведёт на настройки самого UI, дети — на страницы настройки объектов. `Exact: true` не подсвечивает родителя вместо выбранного ребёнка.

Переносить предметные страницы отдельно от оболочки. Не добавлять в общий AppShell обращения к Kafka/LLM/камере или редактирование файлов удалённых сервисов.

## Неподвижная оболочка и независимые панели

`AppShell` занимает viewport; `body` не прокручивается. Верхняя строка не участвует в прокрутке, меню и обычная `shell-content` имеют собственные scroll containers. Для страницы с параллельными панелями использовать `workspace-page`, `workspace-columns` и `workspace-pane`:

```razor
<div class="workspace-page">
    <header class="page-header"><h1>Обзор</h1></header>
    <div class="workspace-columns">
        <section class="workspace-pane" tabindex="0" aria-label="Левая панель">
            <h2 class="workspace-pane-header">Левая панель</h2>
            @* Длинные данные прокручиваются только здесь. *@
        </section>
        <section class="workspace-pane" tabindex="0" aria-label="Средняя панель">...</section>
        <section class="workspace-pane" tabindex="0" aria-label="Правая панель">...</section>
    </div>
</div>
```

Число/ширины колонок задавать в централизованном CSS через `--workspace-columns`; при нехватке ширины горизонтально прокручивается рабочая схема, а не документ. Не убирать `min-height:0` на цепочке flex/grid. Не добавлять второй вертикальный scroll вокруг всей страницы с независимо прокручиваемыми панелями.

Справочные подробности открывать кнопкой `ⓘ` в заголовке конкретного блока и модальным окном. Для native dialog вызывать `showModal()`, а не просто ставить `open`: только модальное открытие даёт инертный фон и управление фокусом. Имена кнопок, заголовки и подробности остаются ресурсами приложения. Полные требования и критерии приёмки — в REQUIREMENTS.md.

## Собственные подсказки

Оболочка загружает `ui-tooltip.js` автоматически при первом интерактивном render; CSS подключён через `shell.css`. Для другого web-стека подключить `ui-tooltip.css` и `<script type="module" src="ui-tooltip.js"></script>` один раз на документ.

Вместо `title` указывать локализованный текст в `data-tooltip`:

```razor
<span data-tooltip="@L["Полное пояснение показателя"]">42</span>
<button aria-label="@L["Подробности"]" data-tooltip="@L["Открыть подробности блока"]">ⓘ</button>
```

Для SVG ставить `data-tooltip` на сам график и, при необходимости, на отдельные сегменты; доступное имя графика сохранять в `aria-label`. Не оставлять SVG `<title>`, вызывающий второе нативное окно. Модуль даёт статическим источникам tabindex, связывает открытое окно через aria-describedby, выводит только textContent, поддерживает переносы строк и отслеживает изменения перевода/значений. Динамические координаты задаются JS; вся палитра, шрифт и размеры — в общем CSS. Popover top layer сохраняет видимость вне scroll panels и внутри native dialog. Большие справочные материалы остаются в ⓘ.

Проверить края viewport, увеличенный курсор, переход мыши на текст, Tab/Shift+Tab и Escape, RU/EN, светлую/тёмную темы. Escape при открытой подсказке сначала закрывает её; следующий Escape может закрыть модальное окно.

## Из другого web-стека

Использовать `themes.css` и семантические токены. Воспроизвести header + sidebar + content, иерархию и активное состояние меню. Плотность хранить как `data-density="nano|mini|norm"`, тему — `data-theme="cream|dark|emerald|light"` на общей оболочке. Стили подключать после reset; не тянуть старый продуктовый CSS.

## Native / MAUI / desktop

Правила, палитры и иконки использовать по смыслу. CSS и Razor не переносятся механически. Сохранить верхнюю служебную строку, компактную навигацию, плотные строки, темы и читаемость. Для сенсорного управления соблюдать платформенные размеры зон попадания.

### Отключаемые подсказки (27.10.2026)
В меню оформления добавлен переключатель «Подсказки → Показывать подсказки». Состояние сохраняется как <StoragePrefix>.tooltips, true/false. ShellOptions.DefaultTooltips задаёт начальное значение (по умолчанию true); Rail использует false. data-tooltips на .lu-shell управляет общим ui-tooltip.js и немедленно закрывает уже видимую подсказку при отключении. Клик не создаёт постоянную подсказку фокуса; клавиатурный фокус и Escape сохранены. Автоматические длинные пояснения не следует размещать на рабочей поверхности интерактивного графика; используйте явную справку ⓘ.
